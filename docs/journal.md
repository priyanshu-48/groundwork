# Groundwork journal (interview reference)

## Major decisions
| Date | Decision | Alternatives | Why |
|---|---|---|---|
| 2026-10-16 | Job queue = Postgres table with `FOR UPDATE SKIP LOCKED` | SQS, Redis/Celery | No extra infra, transactional with the document insert, portable across AWS/Oracle |
| 2026-10-16 | Hand-written tool-calling agent loop | LangChain, LangGraph | Shows understanding of the mechanics; fewer dependencies; full control of limits and citation validation |
| 2026-10-16 | Host-agnostic deploy (Docker Compose, S3-compatible storage, plain Postgres+pgvector) | AWS-native services (Lambda, Cognito, etc.) | AWS free tier ends; planned move to Oracle free tier must be config-only |
| 2026-10-16 | Strict AWS cost/secret guardrails (budget alarm, no NAT/multi-AZ, SSM, instance roles, gitleaks, user runs all AWS mutations) | Ad-hoc | Avoid leaked keys and surprise bills on a free-tier account |
| 2026-10-16 | No Co-Authored-By trailers in commits | Default attribution | Owner's preference: the repo history is the author's own work |
| 2026-10-16 | RustFS replaces MinIO for local/test S3 | SeaweedFS, LocalStack, pinned old MinIO | MinIO's public images were removed; S3 API is the contract, so the app is unaffected (ADR 0001) |
| 2026-10-16 | M1 auth: argon2 hashing off the event loop, HS256 JWT (sub, org_id, exp) with algorithm whitelist, signup creates org+user, identical 401 for unknown email vs wrong password (dummy-hash verify), app refuses to boot without a 32+ char JWT_SECRET | bcrypt, refresh tokens, invites | argon2 is the current OWASP pick; to_thread keeps the loop responsive; whitelist blocks alg=none; no enumeration; fail-closed secret. org_id only ever comes from the verified token |
| 2026-10-16 | M2: upload does S3 put first, then document+job in one DB transaction; reaper fails jobs already at max_attempts instead of requeueing; PDF checked by magic bytes and read in 1 MB chunks capped at 20 MB; native Postgres enums | DB first then S3; plain requeue in reaper; trust content-type | Deterministic key makes S3 retries harmless and avoids rows pointing at missing files; a poison job that kills workers must not loop forever; content-type is client-controlled; never buffer attacker-sized bodies |
| 2026-10-16 | M3 ingestion: slow work (S3, parse, embed, LLM) first, then one transaction that deletes old chunks and inserts new ones; permanent vs transient errors; invoices stored but flagged (partial unique index); embeddings L2-normalized; page/chunk caps; worker refuses to start with AI_PROVIDER=gemini and no key | Hold a DB transaction across the Gemini calls; retry everything; fail the job on bad totals; silently fall back to fake embeddings | No long transactions or half-written state, so a killed worker leaves 0 duplicates; retrying a corrupt PDF is pointless; flagged rows keep evidence without poisoning aggregates; truncated 768-d Gemini vectors are not unit length; caps bound cost; fake embeddings in a real index would silently ruin retrieval |
| 2026-10-16 | M4: synthetic corpus with gold pages known by construction and verified by re-reading the PDFs; retrieval scored on the right contract AND page; fake-embedder numbers blocked from docs/evals.md; free-tier pacing via min-interval throttles; iterative HNSW scan on every search | Detect gold pages by searching text afterwards; score at document level only; allow fake numbers with a label | Ground truth must be correct before any metric means anything; page-level is what citations need; a harness check must not become a resume number; bulk loads would otherwise hit 429s; a selective org filter can starve a plain HNSW scan of results |
| 2026-10-17 | M5: hybrid search = vector top 20 + keyword top 20, fused with RRF, optional FlashRank rerank; keyword leg uses OR semantics, hyphen-split tokens and a digit-term boost; default search_mode = hybrid; eval queries embedded once and cached on disk; harder 60-question retrieval set | Keep AND semantics; rerank by default; re-embed every run | AND found nothing for natural questions; Postgres tokenization of IDs depends on context and ts_rank_cd ignores term rarity; first results showed hybrid best on recall and the reranker slower (~2 s) and worse on exact IDs; the embedding quota is 1000/day, so reruns must not spend it |
| 2026-10-17 | M6: hand-written agent loop over three tools; refs (C1, C2) instead of UUIDs in tool output; citations validated against what the run actually retrieved; retrieved text wrapped in escaped <document> tags; Pydantic tool args forbid unknown fields; generation model fallback chain (never for embeddings); batched invoice extraction (10 per request) via a backfill command; resumable, call-budgeted agent eval with rule-based scoring | LangChain agents; UUID citations; AND-merge of tool and model errors; one invoice per LLM call; LLM-as-judge scoring | Own loop shows the mechanics and keeps limits explicit; short refs cannot be guessed or hallucinated into other tenants' ids; escaping stops planted text closing the wrapper; extra='forbid' rejects a forged org_id; quotas are per model so a chain adds them up; 300 single-invoice calls are impossible on a 20/day quota; judging with rules is free and deterministic |
| 2026-10-16 | graphify knowledge graph for repo navigation | Raw grep each session | Cheaper context, persistent architecture map |

## Roadblocks
| Date | Symptom | Root cause | Fix | Lesson |
|---|---|---|---|---|
| 2026-10-16 | `docker compose up` api crashed: `No module named 'app'` in alembic env.py | Alembic CLI doesn't add cwd to sys.path; pytest masked it because rootdir was on the path | `prepend_sys_path = .` in alembic.ini | Test the container path, not just pytest |
| 2026-10-16 | Compose failed binding 5432 | Windows/another service already holds the port | Host port 5433 (container stays 5432) | Keep host ports configurable |
| 2026-10-16 | Testcontainers `ImageNotFound` for minio/minio | Upstream removed the image | Switched to RustFS | Pin and verify images early |
| 2026-10-16 | Test and compose still referenced MinIO-era patterns after M0 fix: new worker test data leaked across tests (duplicate-invoice test saw other tests' rows) | Shared session-scoped DB and an unscoped SELECT in the test | Scope every test query by the test's own org_id | Tests on a shared DB must filter by their own tenant |
| 2026-10-16 | Fake-embedder retrieval test found the right contract but never the right page | The fake hashed every word, so shared stopwords (the, is, in) made all pages look alike | Drop a small stopword list in the fake | A fake that cannot retrieve cannot validate retrieval code; keep fakes just good enough, and never read quality from them |
| 2026-10-17 | load_corpus.py died with `RemoteProtocolError: Server disconnected` while polling | The poll interval (5 s) equals uvicorn's keep-alive timeout (5 s), so httpx sometimes reused a connection the server had just closed. The API and worker were fine | Retry transport errors in the loader (reconnect) | Look at the server logs before blaming the server; a retry on idle-connection races is normal client behaviour |
| 2026-10-17 | Corpus load stalled at 32 ready / 293 processing | Free-tier generate_content quota is 20 requests per day per model (429 RESOURCE_EXHAUSTED, PerDay). 300 invoice extractions can never fit; embeddings use a separate, larger quota and kept working. Each failed doc also burned 4 pointless immediate retries | Added EXTRACTION_ENABLED=false (invoices still chunked and embedded), stopped retrying PerDay 429s in-process | Read the provider's quota table before designing a bulk job; a rate-limit error that names a daily window must not be retried in seconds. M6 needs a plan for invoice extraction (higher-quota lite model, batching several invoices per request, or a paid tier) |
| 2026-10-17 | First real baseline reported p50=1995 ms, p95=2035 ms | The 2 s embedding throttle (meant for bulk loading) also applied to eval queries, so latency measured the throttle | run_evals builds its settings with the throttle off; regression test added; the bad row and result file were discarded and the eval re-run | A metric that equals a config value is a bug until proven otherwise |
| 2026-10-17 | Baseline vector retrieval already scores recall@5 = 100%, MRR@10 = 0.986 on the 35 contract-lookup questions | Questions name the vendor and echo the clause wording, so even plain vector search finds the page; there is no headroom for hybrid/rerank to show a recall gain | Plan M5 around a harder retrieval set (exact-token queries such as invoice numbers, paraphrases with no shared wording) before comparing modes | Check a benchmark has headroom before using it to claim an improvement |
| 2026-10-17 | Exact invoice-number queries found only half the invoices in keyword mode | (1) tokenization of `V02-2025-0003` differs by surrounding text, (2) `ts_rank_cd` has no IDF so common words beat the ID | Hyphen-split tsv + query (migration 0005), phrase-quote identifiers, boost digit-containing terms | Look at the actual tsvector before blaming ranking; a ranking function without IDF needs help on rare tokens |
| 2026-10-17 | `ORDER BY (0) DESC` raised `ORDER BY position 0 is not in select list` | A bare integer in ORDER BY is a column position | `CAST(0 AS int)` | Generated SQL needs edge cases tested (no identifier terms) |
| 2026-10-17 | Docker build failed: `No module named 'flashrank'` in the model pre-download step | `ENV PATH` for the venv was set after the RUN that needed it | Moved `ENV PATH` before the RUN | Order matters in Dockerfiles; build the image, not just the tests |
| 2026-10-17 | Eval rerun failed with 429 `EmbedContentRequestsPerDayPerProjectPerModel` (limit 1000) | Corpus load (~325 requests) plus several eval runs used the daily embedding quota; I had also deleted the first result JSON before its replacement existed | Query vectors are now cached on disk (also saved when a run fails); rerun after the quota resets | Do not delete an artifact until its replacement exists; treat free-tier quotas as a budget |
| 2026-10-17 | First M5 run (uncommitted tree, numbers printed, to be re-confirmed on a clean commit): easy set vector 100%/0.986, hybrid 97.1%/0.940, rerank 100%/1.000; hard set vector 81.7%/0.704, hybrid 93.3%/0.733, rerank 78.3%/0.714; exact-ID recall vector 50% -> hybrid 100% -> rerank 70%; rerank search p50 about 2.2 s (TinyBERT about 0.25 s on the easy set) | Hybrid fixes exact IDs but adds noise to paraphrases (keyword hits dilute the vector order); the MS MARCO cross-encoder reads meaning, not identifiers, so it demoted the right invoices | Default mode hybrid; reranker kept optional; candidate follow-ups: skip rerank when the query has identifiers, weight RRF per leg, try TinyBERT | A benchmark with headroom showed what a saturated one hid: each stage helps one query type and hurts another |
| 2026-10-17 | Free-tier quotas shaped the whole milestone: 20 generate_content requests/day on one model, 1000 embedding requests/day | Eval design assumed unlimited calls | Fallback chain, batching, resumable eval with a call budget, never-cache-errors | Read the quota page before designing an eval, and make every long run resumable |
| 2026-10-17 | Unverified against the real API: function-declaration JSON schema, batch-extraction schema, thought-signature replay | Only stubs available offline | Documented in ADR 0009; first live run may need small adjustments | State what has not been run, not just what passes |
| 2026-10-17 | First live backfill (gemini-3.5-flash-lite, 10 invoices per call): 293 invoices in 30 calls, but 20 came back flagged `missing fields: total` | The model sometimes copied amounts verbatim with thousands separators ('13,057.07') despite the prompt; `Decimal('13,057.07')` failed so the total became None (the same would have silently dropped subtotal/tax). Re-extracting the same documents in another batch returned plain numbers, so it is nondeterministic | Tolerant `_money` (symbols, thousands separators, decimal commas, JSON numbers; unparseable stays None, never a guess), plus `--retry-flagged` (each document at most once per run). Re-run: 20 invoices in 2 calls, 0 flagged | Validate model output tolerantly but never repair silently: review_reason still checks subtotal + tax == total |
