# 0018: Evidence for computed answers, beside the tool result and stored with the step
- **Context:** contract answers cite the page that states each fact (ADR 0017), but totals ("Ironbridge billed 63,382.54 USD") and "which vendor billed the most" are computed by SQL over extracted rows and pointed at no source (invoice aggregates 10/35 cited, multi-hop 0/20).
- **Decision:** every `query_invoices` and `query_contracts` call also returns **evidence**: the invoices (or contracts) behind the number, with invoice number, vendor, date, total, source file and page, plus per-currency totals computed in SQL over all matching rows. The chat shows it in a collapsed "Evidence" panel under the answer, so a reader can add the rows up and open the sources.
- **Same filter by construction:** the aggregate and the evidence query share one WHERE builder (`invoices_repo._conditions`: validated rows only, payment-terms EXISTS, literal vendor patterns, date range, org id), so the rows cannot drift from what was summed. A test checks evidence totals equal the answer for sum, count, list and grouped queries.
- **Beside the result, never inside it:** the evidence is not sent to the model (no extra tokens, no behaviour change, so the 90-question eval was not re-run) and is stored in a nullable `agent_steps.evidence` JSONB column (migration 0008, additive) so history shows what the agent actually used. At most `EVIDENCE_MAX_ROWS` (100) rows are stored and shown; the totals and count always cover all rows and the UI says when rows are cut.
- **Alternatives:** recompute evidence on demand from the stored tool arguments (a new endpoint taking filters from the client, and it could differ if data changed since the answer); put the rows in the model's tool result (more tokens, and the model could misquote them); register one citation per invoice (hundreds of refs for one sum).
- **Limits:** evidence is a table of rows, not a citation the model chooses, so eval citation coverage is unchanged (10/35 and 0/20); the source column names the file and page but does not open the PDF; money is shown from strings, never floats.
